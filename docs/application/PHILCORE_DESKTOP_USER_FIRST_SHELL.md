# PhilCore Desktop User-First Shell

Phase O.15 changes presentation and navigation only. It does not add a second
Runtime, authority path, chain integration, public account, or public-network
operation.

## Information Architecture

The normal sidebar contains only:

- Home
- Recovery setup
- Activity
- Settings

Identity, Trust, Recovery, and Security are sections within Settings. Ethereum
and the other locally cataloged ecosystems are destinations on Home. Developer
tools are available only in Technical mode when the existing developer
preference is enabled.

The persistent `User | Technical` switch changes only the rendering of the
current authoritative Runtime snapshot:

| User content | Technical content |
| --- | --- |
| identity name, avatar, lock state, and clear next action | identity references, owner commitment, storage metadata |
| local catalog search, favorite chains, and honest availability | adapter status, capability lists, account/deployment state |
| human-readable activity | workflow IDs, stages, evidence, proof and approval details |
| session timeout, auto-lock, identity name | release, package, signing, notarization, and Gatekeeper diagnostics |
| trusted-device explanation and manageable credential state | evidence class, credential metadata, trust evaluation state |
| recovery explanation and Alpha limitations | recovery authority, workflow, custody, rotation, and local drills |
| protected Mac unlock controls | platform-authentication implementation details |

Approval presentations remain Runtime generated and digest-bound in both modes.
Technical mode cannot bypass trust, policy, approval, user presence, proof
verification, Device Vault signing, or local-only network restrictions.

## Identity And Home

First launch is a standalone, narrow Welcome screen with no sidebar,
presentation switch, diagnostics, or package details. It shows the approved
product positioning, a locally generated Phil preview, a deterministic
randomize control, `Create Phil`, and returning identities when available.
Identity creation is also standalone.

Identity creation keeps the existing passphrase policy, confirmation, and
show/hide controls. All five requirements and confirmation matching update
while the user types. The local display name defaults to `My Phil`, remains
editable in Settings, and does not change the identity root or owner
commitment.

The Phil preview is generated by a bundled local provider. The selected safe
trait reference persists with the identity as decorative metadata. Its source
is `local-preview`, its mint status is `not-minted`, and it has no public token.
No NFT, mint, chain request, wallet, or public account is claimed.

Home is a portal containing the selected identity, lock state, an inert World
ID preview, local catalog search, clearly labeled bundled ecosystem examples,
favorite chains, and four recent events. World ID is modeled only as a future
optional credential/trust signal; no SDK, request, biometric collection, or
identity-root authority is enabled. Search and featured examples use only
bundled data and perform no remote request.

## Chain Catalog

The bundled catalog currently contains Ethereum, Bitcoin, Solana, Base,
Polygon, Cardano, Arbitrum, and Optimism. Ethereum is labeled `Local Alpha`
because the reviewed local fixture path exists. Every other entry is labeled
`Preview`. Preview pages provide information and a path back to Home, but no
action button.

The Ethereum action still calls the existing protected-action lifecycle. In
current source it completes preflight and Runtime approval, then stops safely
at the quarantined secret-bearing STWO proof boundary before a signing approval,
Device Vault signing, nullifier consumption, or local EntryPoint execution.
Nothing is sent publicly. A future witness-hiding proof backend must pass its
own admission gate before this path may advance further.

Chain destinations also expose an explicit account-status model: `none`,
`local-test`, `prepared`, `deployed-testnet`, `deployed-mainnet`, or
`unavailable`. Ethereum can explain the local ERC-4337 test setup without
claiming a public deployment. Unsupported previews do not create accounts.

## Activity Retention

Home renders only four events. Activity incrementally reveals the complete
history currently available to the Runtime snapshot.

The encrypted identity registry retains its existing durable audit trail.
Process-only UI/session events remain process-local and do not survive restart.
O.15 removes the prior 120-event in-process truncation, but intentionally does
not introduce a database migration. A future audit-storage phase should define
durable retention, deduplication, indexing, and pagination as an explicit
storage boundary.

## Packaged Walkthrough

Run:

```bash
npm run desktop:test-packaged-user-shell
```

The packaged automation covers the standalone first launch, local Phil
randomization, live passphrase feedback, named identity creation, Home,
World ID preview, bundled discovery examples, User/Technical switching, local
search, honest account statuses, the Ethereum proof-quarantine stop, a preview chain,
Activity history, Settings sections, protected Mac enrollment, Technical
developer diagnostics, relaunch, returning identity selection, protected
unlock, preview/name persistence, and public-network disablement.

The current shell also applies the approved Phil visual direction: obsidian
surfaces, green readiness signals, pink navigation energy, destination-like
network cards, and a short door-opening transition after a real successful
vault unlock. The transition is inert, receives no input, and has a reduced-
motion path.

Physical human review is still required for final visual polish, keyboard and
screen-reader quality, real native macOS user presence, window-size behavior,
and the clarity of security copy under real interaction.
