# O.43 Native iPhone Security and Threat Analysis

> Historical O.43 phase record. Current source has changed materially and a
> later, narrow physical-device disposable-key observation exists. See
> [Secure Enclave Validation Status](./SECURE_ENCLAVE_VALIDATION_STATUS.md).

## Protected assets and trust boundaries

The Role 1 private key is generated by Security.framework as a P-256 key in
the Secure Enclave on a physical iPhone. Its access control is
`kSecAttrAccessibleWhenUnlockedThisDeviceOnly` plus
`privateKeyUsage | userPresence`. The application stores only a key tag and
safe public metadata. Synchronization is explicitly disabled.

The iPhone does not store:

- the offline Role 2 factor;
- desktop Device Vault material;
- the execution-validator private key;
- a generic Ethereum wallet key;
- a desktop pairing private key after the process operation;
- a production recovery signature.

Simulator keys are software-backed, tagged
`O43_DISPOSABLE_IOS_SECURE_ENCLAVE_RECOVERY_TEST_ONLY`, and marked
`simulatorOnly=true`. The production descriptor builder and Solidity verifier
reject that classification.

## Findings

No known Critical or High issue remains in the implemented source and
synthetic tests. Physical-device and simulator build gates are unexecuted
because full Xcode is not installed, so the phase remains blocked for
production ceremony.

### App uninstall persistence — Medium, mitigated by policy

iOS Keychain items can survive application uninstall. Uninstall is therefore
not accepted as key deletion. The user must invoke in-app deletion and
complete desktop invalidation or rotation before removing the app. A reinstall
with the same Team ID, bundle ID, and access group may regain the item. A
device erase destroys it; `ThisDeviceOnly` prevents backup restoration to a
different device.

### Hardware-origin claim — Medium, explicitly not claimed

The on-chain verifier cannot prove that a P-256 public key came from Secure
Enclave. It verifies exact membership, signature, and pinned enrollment policy.
Physical enrollment checks establish local evidence. App Attest is deferred
optional enrollment evidence and is not required at recovery time.

### Direct local HTTP — Low after application encryption

The LAN endpoint uses HTTP on one private interface. A hostile LAN peer can
observe connection metadata and attempt requests. It cannot derive the ECDH
secret, alter AES-GCM content, substitute the transcript, replay a used
session, or make the desktop accept an unapproved credential. TLS can be added
later for transport privacy; it must not replace transcript binding.

### Static-analysis findings — Medium/Informational, reviewed

Pinned Slither 0.10.4 completed against the current Hardhat build. The changed
verifier produced no High or Critical finding. Its two Medium reports are the
existing OpenZeppelin `ECDSA.tryRecover` third error-argument result being
ignored while the returned `RecoverError` is checked and every non-`NoError`
case is rejected. Its Informational reports identify reviewed fixed-offset
assembly reads. Length and canonical-layout guards execute before those reads,
and deterministic truncation, extension, and malformed-evidence tests reject
the unsafe shapes. No new state, external call, or mutable authority was added
to the verifier.

## Key lifecycle

- Generation starts at `1`.
- Replacement must increment by exactly one.
- The application tag is versioned and generation-specific.
- Public metadata includes the generation and paired identity commitment.
- The desktop encrypted descriptor store rejects same-generation overwrite.
- Lost-device marking does not pretend to erase an inaccessible phone; it
  drives recovery-configuration rotation.
- No private-key export API is exposed. A test-only boolean probe discards any
  returned representation and asserts that a physical Secure Enclave key is
  non-exportable.

## Logs and crash data

The LAN host returns stable error codes and never logs request bodies,
ciphertext, public keys, signatures, session keys, or challenges. Electron
crash upload remains disabled. The renderer gets a QR data URL, safe public
fingerprint, expiry, selected interface label, and public descriptor status.
The iOS app stores no crash reporter integration in O.43.

## Stop boundary

O.43 performed no deployment, public transaction, Sepolia or RPC access,
bundler submission, fund movement, production account creation, production
credential ceremony, private-key export, TestFlight/App Store action, Apple
Developer portal mutation, or push.
